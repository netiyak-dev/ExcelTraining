# ชุดการเรียนรู้ Excel และ Google Sheets สามระดับ — ซอร์สโค้ด

โฟลเดอร์นี้คือ **ต้นทางของทุกอย่าง** ในโครงการ ไฟล์ที่อยู่ในโฟลเดอร์ `00` ถึง `08` ล้วนสร้างจากที่นี่
ถ้าจะแก้เนื้อหาบทเรียน สไลด์ ไฟล์ตัวอย่าง หรือเอกสาร **ให้แก้ที่นี่แล้วสั่ง build ใหม่**
อย่าแก้ไฟล์ HTML หรือ .docx ที่สร้างเสร็จแล้วโดยตรง เพราะจะถูกเขียนทับในการ build ครั้งถัดไป

---

## เริ่มใช้ใน 3 คำสั่ง

```bash
cd "09 ซอร์สโค้ด"
npm install                  # ครั้งแรกครั้งเดียว ใช้สำหรับสร้าง .docx และ .pptx
pip3 install openpyxl        # ครั้งแรกครั้งเดียว ใช้สำหรับสร้าง .xlsx

bash build_all.sh            # สร้างทุกอย่าง ผลลัพธ์ลงโฟลเดอร์ ผลลัพธ์/
bash build_all.sh web        # สร้างเฉพาะหน้าเว็บ เร็วกว่ามาก ใช้ตอนแก้บทเรียน
npm run serve                # เปิดดูที่ http://localhost:8080
```

ต้องการ Python 3.9 ขึ้นไป และ Node 18 ขึ้นไป

## งานที่ทำบ่อยที่สุด — แก้เนื้อหาบทเรียน

เนื้อหาแยกออกจากตัวเรนเดอร์โดยสิ้นเชิง แก้เนื้อหาไม่ต้องแตะโค้ดหน้าเว็บ

| จะแก้อะไร | แก้ที่ไฟล์ |
|---|---|
| เนื้อหา สไลด์ย่อย แบบฝึกหัด ควิซ ของระดับ Beginner | `lesson_beginner.py` |
| เนื้อหาระดับ Intermediate รวมโมดูลจดหมายเวียน | `lesson_intermediate.py` |
| เนื้อหาระดับ Advanced | `lesson_advanced.py` |
| หน้าแรกสาธารณะ ลิงก์ CONFIG ผังการเรียน | `build_site.py` |
| หน้าตาและ JavaScript ของหน้าเรียนทุกระดับ | `build_lesson.py` |

แก้แล้วสั่ง `bash build_all.sh web` ใช้เวลาไม่ถึงวินาที

โครงสร้างเนื้อหาในไฟล์ `lesson_*.py`

```python
MODULES = [{
    "id": "m1", "no": "1", "time": "0–25 นาที",
    "title": "...", "intro": "...",
    "blocks": [ ... ],            # ชนิดบล็อกดูตารางข้างล่าง
    "workshop": { "code": "1.1", "builder": "table", ... },
}]
QUIZ = [...]        # แบบตรวจความเข้าใจท้ายหน้า
CHECKLIST = [...]   # รายการตรวจก่อนส่งงาน
LEVEL = {...}       # ชื่อระดับ คีย์ที่ใช้เก็บงานในเบราว์เซอร์ ลิงก์ในสารบัญ
LABS = [...]        # ห้องฝึกโต้ตอบที่เป็นหัวข้อของตัวเอง
BUILDERS = {...}    # ห้องฝึกโต้ตอบที่ฝังอยู่ในแบบฝึกหัด
```

ชนิดบล็อกที่ใช้ได้ใน `blocks`

| kind | ใช้ทำอะไร |
|---|---|
| `grid4` | การ์ดสี่ช่อง หัวข้อกับคำอธิบายสั้น |
| `twocol` | เทียบสองฝั่ง ควรทำกับไม่ควรทำ |
| `table` | ตารางเปรียบเทียบ |
| `steps` | ขั้นตอนมีลำดับ |
| `stat` | ตัวเลขเด่นพร้อมคำอธิบาย |
| `sheetpair` | **ภาพจำลองหน้าจอสเปรดชีตคู่ผิดถูก** ใช้บ่อยที่สุดและสื่อสารได้ดีที่สุด |
| `tip` `warn` `why` `rule` | กล่องข้อความสี่แบบ |

**เนื้อหา** — แก้บ่อย
`lesson_beginner.py` `lesson_intermediate.py` `lesson_advanced.py`

**สไลด์**

**เอกสาร**

`build_guide.js` คู่มืออาจารย์ · `build_setup_guide.js` คู่มือติดตั้งระบบ

**อื่น ๆ**

`build_previews.js` สร้างหน้าพรีวิวจากโค้ด .gs จริงโดยไม่ต้อง deploy

## นำขึ้นเว็บด้วย GitHub Pages

หน้าเว็บทั้งสี่ไฟล์เป็น static ล้วน ไม่มีการอ้างอิงไฟล์ภายนอกแม้แต่ไฟล์เดียว จึงวางที่ไหนก็ทำงานทันที

> **ก่อนเริ่ม** โฟลเดอร์นี้มีโฟลเดอร์ `.git` ที่ถูกสร้างไว้ตอนทดสอบ `.gitignore` และค้างอยู่ในสภาพใช้ไม่ได้
> ให้ **ลบโฟลเดอร์ `.git` ทิ้งก่อน** แล้วจึงเริ่มตามขั้นตอนด้านล่าง
> บน macOS กด Cmd+Shift+จุด ใน Finder เพื่อให้เห็นโฟลเดอร์ที่ขึ้นต้นด้วยจุด หรือใช้คำสั่ง `rm -rf .git`

```bash
cd "09 ซอร์สโค้ด"
rm -rf .git                  # ลบ repo ที่ค้างจากการทดสอบก่อน
git init && git add -A && git commit -m "ชุดการเรียนรู้ Excel และ Google Sheets"
git branch -M main
git remote add origin https://github.com/<ชื่อบัญชี>/<ชื่อ repo>.git
git push -u origin main
```

จากนั้นไปที่ **Settings → Pages → Source** เลือก **GitHub Actions**
ไฟล์ `.github/workflows/deploy.yml` จะ build แล้ว deploy ให้เองทุกครั้งที่ push

ทางเลือกอื่นที่ง่ายกว่าถ้าไม่อยากใช้ git คือลากโฟลเดอร์ `ผลลัพธ์/หน้าเว็บ` ไปวางที่
Cloudflare Pages หรือ Netlify ซึ่งรับ drag and drop โดยตรง

**ชื่อไฟล์ภาษาไทย** ใช้งานได้ปกติ แต่ URL จะถูกเข้ารหัสเป็น `%E0%B8%AB...` ซึ่งอ่านยาก
ถ้าต้องการ URL สวยให้แก้ค่า `lesson` ของแต่ละระดับใน `build_site.py` เป็นชื่ออังกฤษ
เช่น `lesson-beginner.html` แล้วแก้ชื่อไฟล์ปลายทางใน `build_all.sh` ให้ตรงกัน

## ส่วนที่ย้ายไป static hosting ไม่ได้

ระบบนี้มีสองส่วนที่ทำงานคนละที่ และต้องเป็นเช่นนี้

| ส่วน | อยู่ที่ไหน | เพราะอะไร |
|---|---|---|
| หน้าแรก และหน้าเรียนสามระดับ | static host ที่ใดก็ได้ | เป็น HTML ล้วน ไม่ต้องรู้ว่าใครเปิด |
| หน้าผลแบบทดสอบ และหน้าคลังไฟล์ | **Apps Script Web App เท่านั้น** | ต้องใช้ `Session.getActiveUser().getEmail()` เพื่อรู้ว่าใครเปิด แล้วเทียบกับชีต Roster |

หน้าเว็บ static แค่ลิงก์ออกไปหา Web App ทั้งสอง โครงสร้างจึงไม่ต้องเปลี่ยนเลยเมื่อย้ายโฮสต์
ลิงก์เหล่านั้นตั้งค่าในส่วน `CONFIG` ต้นไฟล์ `build_site.py`

## กฎความปลอดภัยของ repo

`.gitignore` กันไว้ให้แล้ว แต่ควรรู้เหตุผลเพื่อไม่เผลอบังคับเพิ่มเข้าไป

1. **ห้ามให้ไฟล์เฉลยขึ้น repo** — `ผลลัพธ์/เฉลย/` และคู่มืออาจารย์ถูกกันไว้ ถ้าหลุดขึ้น repo สาธารณะเท่ากับแจกเฉลยให้ทุกคน
2. **ห้ามให้ข้อสอบจัดระดับขึ้น repo** — กันไว้สี่ไฟล์คือ `items.json` ซึ่งเป็นต้นทางของข้อสอบทั้ง 18 ข้อพร้อมเฉลย
   กับไฟล์ที่สร้างจากมันคือ `1_BuildPlacementForm.gs` `2_ScoreAndNotify.gs` และ `Placement_ItemBank.csv`
   เพราะข้อสอบชุดนี้ใช้กับผู้เรียนรุ่นถัดไปด้วย ถ้าหลุดต้องออกข้อสอบใหม่ทั้งชุด

   ผลข้างเคียงคือ ผู้ที่ clone repo มาจะสร้างแบบทดสอบจัดระดับใหม่ไม่ได้จนกว่าจะคัดลอก `items.json`
   มาวางเอง `build_all.sh` ตรวจให้แล้วและจะข้ามสองขั้นนั้นไปพร้อมแจ้งเหตุผล โดยไม่ถือว่า build ล้มเหลว
   ตัวไฟล์เก็บไว้ใน Google Drive โฟลเดอร์ 05 หรือในเครื่องผู้สอน

   ถ้าตั้ง repo เป็นแบบส่วนตัวและมั่นใจว่าเข้าถึงได้เฉพาะผู้สอน จึงลบสี่บรรทัดนั้นออกจาก `.gitignore` ได้
3. **ห้ามให้ไฟล์รายชื่อผู้รับจริงขึ้น repo** — มีชื่อ อีเมล ตำแหน่ง และคะแนน ซึ่งเป็นข้อมูลส่วนบุคคล ไฟล์ที่อยู่ในโครงการเป็นข้อมูลสมมติที่สร้างจากสคริปต์ จึงขึ้นได้
4. **หน้าเรียนมีเฉลยอยู่ในโค้ดฝั่งผู้ใช้** — ทั้งเฉลยควิซ เฉลยล่าสูตรผิด และเฉลยกรณีจริยธรรม ใครกดดูซอร์สก็เห็นหมด
   ข้อนี้เป็นจริงมาตั้งแต่ตอนฝังใน Google Sites แล้ว ไม่ใช่ความเสี่ยงใหม่ แต่เมื่อขึ้นโฮสต์สาธารณะจะหาเจอง่ายขึ้นมาก
   workflow จึงตั้ง `NOINDEX=1` ไว้ให้ ซึ่งใส่ `<meta name="robots" content="noindex, nofollow">` ในหน้าเรียนทั้งสามหน้า
   ถ้าต้องการปิดกั้นจริงจังกว่านั้น ต้องย้ายหน้าเรียนไปอยู่หลัง Apps Script เหมือนคลังไฟล์

## หลักการที่ใช้ตลอดโครงการ

เขียนไว้เพื่อให้คนที่มาแก้ต่อรักษาไว้ได้

**เฉลยต้องคำนวณจากไฟล์ที่ส่งมอบจริง ไม่ใช่จากบันทึกตอนสร้าง**
`answer_key.py` เปิดไฟล์ .xlsx ที่สร้างเสร็จแล้วมาอ่านค่า ตัวเลขในเอกสารทุกฉบับจึงไม่มีทางไม่ตรงกับสิ่งที่ผู้เรียนเห็น
ถ้าเปลี่ยนวิธีสร้างข้อมูล เฉลยจะเปลี่ยนตามเองโดยอัตโนมัติ

**ทุกตารางสรุปต้องกระทบยอดได้**
ชีตตารางสรุปแบบ Pivot ในไฟล์เฉลยคำนวณผลรวมด้วยสองวิธีที่ไม่เกี่ยวข้องกัน คือ `SUMIFS` กับ `SUMPRODUCT`
สองค่าต้องเท่ากันทุกแถว และช่องร้อยละต้องรวมได้ 100 พอดี
กฎข้อนี้เคยจับข้อผิดพลาดจริงได้สี่อย่างที่มองด้วยตาไม่เห็น รวมถึงชื่อกลุ่มที่ต่างกันเพียงตัวพิมพ์ใหญ่เล็ก
ซึ่ง `SUMIFS` มองเป็นกลุ่มเดียวกันจึงนับซ้ำ ทำให้ร้อยละรวมได้ 157

**สไลด์ตรวจ layout ด้วยตัวเลข ไม่ใช่ด้วยสายตา**
เครื่องที่ build ไม่มีฟอนต์ไทย การเปิดดูจึงเห็นเป็นสี่เหลี่ยมเปล่า `deck_lib.js` จึงคำนวณความสูงที่ข้อความต้องใช้
แล้วเตือนเมื่อข้อความล้นกรอบหรือกล่องซ้อนทับ ห้ามลบขั้นตอนนี้ออก

**ภาพประกอบในสไลด์เป็นตารางจริงของ PowerPoint ไม่ใช่ภาพนิ่ง**
ด้วยเหตุผลเดียวกันเรื่องฟอนต์ และทำให้ผู้สอนแก้ข้อความในสไลด์ได้เอง

**ทดสอบหน้าเว็บด้วย jsdom**
ห้องฝึกโต้ตอบทุกชุดถูกทดสอบด้วยการจำลองการกดจริง ทั้งกรณีตอบถูกและกรณีตอบผิดแบบที่ผู้เรียนมักทำ
ถ้าเพิ่มห้องฝึกใหม่ ควรเขียนการทดสอบแบบเดียวกันด้วย

## ตรวจว่า build ยังถูกต้อง

```bash
bash build_all.sh                       # ต้องไม่มี error และสไลด์ต้องขึ้นว่า ผ่านทั้งหมด
python3 verify_samples.py ผลลัพธ์/ไฟล์ตัวอย่าง   # กับดักในไฟล์ตัวอย่างต้องครบ
npm run check                           # ตรวจไวยากรณ์ตัวสร้างสไลด์
```

การ build ซ้ำให้ผลเหมือนเดิมทุกครั้ง ตรวจแล้วว่าเนื้อหาในไฟล์ .xlsx และ .pptx ตรงกันทุกไฟล์
ที่ขนาดไฟล์ต่างกันเล็กน้อยเป็นเพราะรูปแบบ zip ฝังเวลาที่สร้างไว้ข้างใน ไม่ใช่เนื้อหาเปลี่ยน
